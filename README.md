# Playwright Script Builder (Code Writer)

A powerful Electron-based desktop application that provides a visual interface for generating, editing, and executing Playwright E2E tests. 

This tool is designed to bridge the gap between manual QA and automated testing by allowing users to visually click through a website and automatically generate perfectly structured Playwright code integrated directly into your existing framework.

---

## 🌟 Key Features

- **Visual DOM Scanner:** Click elements on any live webpage to instantly auto-generate exact Playwright selectors (by `testid`, `role`, `text`, `css`, or `xpath`).
- **Drag-and-Drop Test Builder:** Build test flows visually. Easily reorder, edit, disable, or delete test steps. 
- **Undo / Redo History:** Accidentally deleted a step? Just press `Ctrl + Z` to bring it back.
- **Live Test Runner:** Run your built tests instantly inside a visual popup. Automatically bypasses bot-detection (Cloudflare) and utilizes saved authentication sessions.
- **Native Framework Integration:** Point the app at your existing Playwright repository. It will dynamically scan your `tests/` directory to detect workspaces, read your `.env` files, and manage your file tree automatically.
- **GitHub Integration:** Commit and push generated test scripts directly to your GitHub repository from within the app using a Personal Access Token (PAT).

## 📦 Building & Distribution

This application uses `electron-builder` to package native executables for distribution.

### ☁️ Automated Cloud Builds (Recommended)
This repository is configured with a GitHub Actions workflow (`.github/workflows/release.yml`). 
**Whenever you push code to the `main` branch**, GitHub will automatically boot up cloud servers to build the application for you.
- It builds a Windows `.exe`
- It builds a macOS `.dmg` / `.app`
- Both files are automatically uploaded to the **Releases** section of your GitHub repository.

### 💻 Local Builds
If you want to package the app locally on your machine:
```bash
npm run release
```
*Note: Due to Apple's strict code-compilation rules, you cannot build a macOS release directly from a Windows machine. Use the GitHub Actions cloud build instead.*

## 📖 How to Use

1. **Link your Framework:** Click the **Settings** (⚙️) button in the top right. Set your `Framework Path` to the absolute path of your Playwright E2E repository.
2. **Add GitHub Credentials:** In the settings, add your GitHub Username, Email, and a Personal Access Token (PAT) so the app can commit code for you.
3. **Start Building:** 
   - Enter a URL and click **Visual Inspector**.
   - A new window will open. Click on elements in the page, and the app will record your actions.
   - You can also manually add steps like *Click*, *Fill*, *Navigate*, or *Assertions*.
4. **Run Live:** Click the **Run Test** button to execute the code in real-time.
5. **Save & Push:** Give your test a name and click **Save**. You can then use the Git commands in the UI to push your new test script to GitHub.

## ⚠️ Troubleshooting Warnings

Because the `.exe` and `.dmg` files generated by GitHub Actions do not have expensive, paid Cryptographic Code Signing Certificates, your operating system will warn you the first time you try to install it.

**Windows (SmartScreen):**
- You will see a blue "Windows protected your PC" screen complaining about an "Unknown Publisher".
- Click **More info**, then click **Run anyway**.

**macOS (Gatekeeper):**
- You will see an error saying the "App cannot be opened because the developer cannot be verified."
- Do not double-click the app. Instead, **Right-click** (or Control-click) the `.app` file, select **Open**, and then click the **Open** button in the warning prompt.
